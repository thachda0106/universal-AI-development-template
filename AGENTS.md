# AGENTS.md — Antigravity Setup Template (Source Repo)

This file is **manually maintained** for the template repo itself.
It is NOT the adapter-generated `AGENTS.md` that downstream projects receive.

## What This Repo Is

This is the **Universal AI Dev Template** — a tool-agnostic AI configuration framework.
There is no app code, no build system, no test runner, no package manager.
Everything is YAML frontmatter + Markdown content files, Bash automation scripts, and adapter translation layers.

## Commands

```bash
# The "test suite" — always run after changes
bash .ai/scripts/validate-template.sh

# Install template for your own AI tools after making adapter changes
bash .ai/scripts/install-ai-template.sh
bash adapters/opencode/install.sh
bash adapters/claude/install.sh
bash adapters/antigravity/install.sh
bash adapters/cursor/install.sh
bash adapters/aider/install.sh
```

**validate-template.sh** is the only verification. It checks: directory structure, YAML frontmatter, agent↔workflow cross-references, agent↔skill cross-references, tool-specific reference leaks, unresolved placeholders, and adapter completeness.

## Architecture

```
.ai/           ← Canonical source of truth (edit here)
adapters/      ← Tool-specific translators (changes here must follow ADAPTER_SPEC.md)
```

- `.ai/context/` — PROJECT.md, CONVENTIONS.md, BOUNDARIES.md. **PROJECT.md and CONVENTIONS.md contain `{{placeholders}}` intentionally.** These are templates filled in by downstream projects. Validation warnings about them are expected.
- `.ai/agents/` — 7 canonical agent definitions (YAML frontmatter: `name`, `description`, `skills`, `boundaries`)
- `.ai/workflows/` — 29 step-by-step task workflows (YAML frontmatter: `description`, `agent`)
- `.ai/skills/` — 8 atomic reusable procedures (YAML frontmatter: `name`, `description`, `category`, `inputs`, `outputs`)
- `.ai/prompts/system.md` — shared system prompt (fully written, no placeholders)
- `.ai/scripts/_lib.sh` — shared shell library with `merge_context_files()`, color constants, dry-run support

## Subsystem: Life Systems Engineering

A parallel subsystem applying software engineering to personal life management.
- Config: `.ai/life-config.yaml` (per-device journal path)
- Agent: `.ai/agents/life-engineer.agent.md`
- Skill: `.ai/skills/life-engineering-daily-practices/SKILL.md`
- 12 daily/weekly/on-demand workflows under `.ai/workflows/life-*.md`
- Journal data lives in a **separate git repo** (not in this repo)
- Life Engineering code must never assume a journal path — read from `life-config.yaml`

## Shell Script Conventions

- `set -euo pipefail` in every script
- Source `_lib.sh` for shared utilities; never re-implement `merge_context_files()`
- Always check `.ai/` exists before proceeding
- Scripts must be **idempotent** (safe to run multiple times)
- Print what you create/modify; exit 0 on success

## File Naming Conventions

| Component | Pattern | Example |
|-----------|---------|---------|
| Agent files | `{name}.agent.md` | `bug-hunter.agent.md` |
| Workflow files | `{verb}-{noun}.md` | `create-feature.md` |
| Skill directories | `{verb}-{noun-phrase}/` | `diagnose-bug-root-cause/` |
| Context files | `UPPERCASE.md` | `PROJECT.md` |
| Scripts | `{verb}-{noun}.sh` | `install-ai-template.sh` |

## Adding or Changing Modules

1. Create/modify content in `.ai/` following the naming convention above
2. Register the module name in `.ai/AI_MANIFEST.yaml` under the correct `modules.*` list
3. Run `bash .ai/scripts/validate-template.sh`
4. If the change affects adapter output, test at least one adapter: `bash adapters/<tool>/install.sh`

## Boundaries (from .ai/context/BOUNDARIES.md)

- Never skip approval gates — Scratchpad → Plan → Tasks is sequential with hard stops
- Never modify >3 files for a single task without verifying scope
- Never read `.env` files, secrets, or credentials
- Never run `rm -rf`, force pushes, or destructive operations without explicit approval
